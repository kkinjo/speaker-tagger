## 1. 画面構成

3列の表。ヘッダ行は固定（`position: sticky` でスクロール追従）。

| 列 | 内容 | 幅 |
|---|---|---|
| 1 | 話者 ／ 原文（読み取り専用） | 可変 |
| 2 | 再変換ボタン（↻） | 固定（`.refine-col-status`） |
| 3 | 話者・ステータス・出力内容 | 可変 |

### 3列目の構造

セル内を上下2段に分ける。

```
┌─────────────────────────────────┐
│ 琉球中/金城            AI変換済み │  ← 小さめの文字。左に話者、右にステータス
├─────────────────────────────────┤
│ 2条改正の理由について確認。      │  ← 本文
└─────────────────────────────────┘
```

- 上段の話者は1列目と同じ内容。**冗長だが省略しない。** 3列目だけを見て出力内容が
  把握できる状態を保つため
- ステータスは全体仕様 第4.5章のラベルをそのまま文字で表示する。話者の横なので横幅に
  余裕があり、色ドットのような省略表現は不要。文字色は残すが、色は文字の補助として使う
- 未変換・失敗の行は、下段に原文を薄いグレーで表示する。この時点では `textarea` では
  なく単なるテキスト（`div[role=button]`。クリックと Enter で開く）
- クリックすると `textarea` に変わり、**原文が入った状態**で編集が始まる。そこで何も
  直さずに確定すれば「手修正済み」になる（第7章）
- 変換済・手動修正済の行は、最初から `textarea` で通常の濃さ。高さは内容に合わせて自動で伸びる
- 「変換中」の行は、下段を原文グレーのまま据え置き、上段のラベルを点滅させる
  （`@keyframes refine-pulse`）。スピナーを下段に置くと行の高さが変わってガタつく
- 議題見出し行（`kind === "heading"`）は整文の対象外。`colSpan` で1行にまとめて表示し、
  操作ボタンを置かない
- 1列目は編集不可。直したい場合は①へ戻る
- 行は `memo` 化してある。数百行を毎回描き直さないため（`TableView.tsx` の Row と同じ考え方）

### 失敗行の扱い

再変換に失敗した行に既存の整文結果がある場合、下段はその結果を残したままラベルだけ
「失敗」にする。原文グレーに戻すと、③に実際に出る内容（＝以前の整文結果）と画面表示が
ずれるため。実装上も「失敗」は `transient` の一時状態で、`refinements` には触れない。

## 2. ツールバー（`.refine-toolbar`）

左から順に。

- 「一括変換」ボタン（変換中は「中断」に入れ替わる）
- 「変換済みの行もやり直す」チェックボックス
- 進捗表示（`○ / ○ 行 完了`）
- **文体プリセットの選択**（第3章）
- **表示の絞り込み**（「すべて」／「「原文のまま出力」の行だけ」）
- （右寄せ）「固有名詞」ボタン（ドロワーを開閉。第4章）／ 保存状態

その下に2つの帯を置く。

| 帯 | 内容 |
|---|---|
| `.refine-note` | 選択中プリセットの補足（`hint`）と、「切り替えても変換済み・手修正済みの行はそのままです」の注記。常時表示 |
| `.refine-error-note` | 直近の失敗理由。`role="alert"`。「閉じる」で消える。失敗が無ければ出ない |

①③への遷移は、このツールバーではなくページ上部の共通ナビゲーション
（`ProjectNav`、`refine/page.tsx` の `<header className="topbar">`）にある。

### 絞り込みが必要な理由

3列目が常に埋まっている（未変換の行も原文が表示される）ため、スクロールして残作業を
目で数えることができない。絞り込みで0行になることをもって、処理漏れがないと確認する。
進捗表示だけでは「どの行が残っているか」に辿り着けない。

絞り込み中は議題見出し行も隠す。残すと「0行になった」の確認が成立しない。
0行のときは「「原文のまま出力」の行はありません。処理漏れはありません。」と表示する。

**「表をコピー」はここに置かない。** 出力は③に一本化する。

## 3. 文体プリセット

会議体によって求められる文体が違うため、語尾処理の方針を切り替えられるようにする。

| id | 名称 | セレクト下の補足（`hint`） |
|---|---|---|
| `formal`（既定） | 公式議事録 | 体言止めにして固い文体にする。会長会・校長会向け |
| `plain` | 発言そのまま | 丁寧語を残して柔らかい文体にする。副会長会・特支・幼稚園部会向け |

差分は語尾処理（`endingPolicy`）の1項目だけ。フィラー除去・言い淀みの統合・冗長圧縮は共通。

```ts
// src/lib/refine.ts
export type PromptPreset = {
  id: string;
  name: string;
  /** 利用者向けの補足。UI のセレクトに添える */
  hint: string;
  /** 語尾処理の方針。共通プロンプトに差し込む差分はここだけ */
  endingPolicy: string;
};

export const PROMPT_PRESETS: PromptPreset[] = [
  {
    id: "formal",
    name: "公式議事録",
    hint: "体言止めにして固い文体にする。会長会・校長会向け",
    endingPolicy:
      "- 文末の「〜です」「〜ます」「〜ですね」「〜なんですけれども」等の語尾を落とし、\n" +
      "  体言止めまたは連体形で終える\n" +
      "- 意味が変わる、または文として成立しなくなる場合のみ語尾を残す",
  },
  {
    id: "plain",
    name: "発言そのまま",
    hint: "丁寧語を残して柔らかい文体にする。副会長会・特支・幼稚園部会向け",
    endingPolicy:
      "- 語尾は変更しない。「です」「ですね」「ですか？」等の丁寧語はそのまま残す\n" +
      "- 体言止めにはしない",
  },
];
```

選択値は `Project.promptPresetId` に保存。未設定・未知の id は `getPreset()` が
`formal` に倒す。`PATCH /api/projects/{id}` 側でも `isPresetId()` で検査する。

**プリセット一覧はサーバーコンポーネント（`refine/page.tsx`）が読んで props で渡す。**
`@/lib/refine` は API キーの読み取りと Anthropic API 呼び出しを含むため、
クライアントバンドルへ持ち込まない。

### 「可能な範囲で」を使わない理由

当初 `formal` 側を「可能な範囲で体言止めにする」としていたが、実データではほぼ効かず、
`plain` との差が「〜なんですが」→「〜ますが」程度にとどまった。

「可能な範囲で」は「難しければやらなくてよい」と読める。原則と例外を逆にし、
**残すほうに理由を要求する**書き方に変更した。

### 現状の到達点

修正後も、実際の出力は「常体化」にとどまり、体言止めには至っていない
（「展開しています」→「展開している」）。文中の「〜なんですけど」は敬体のまま残るため、
敬体と常体が混在する。

実用上の支障は無いため当面このままとする。さらに強めるか、常体への統一を明示するかは
未決（全体仕様 第6.3章）。

### 切り替え時の注意

プリセットを途中で切り替えても、既にある `refinements` は自動的には変わらない。全体へ
反映するには「変換済みの行もやり直す」を明示的に使う。変換を始める前に選ぶもの、という
位置づけをセレクトのすぐ下（`.refine-note`）に常時表示する。変換中はセレクトを無効化する。

## 4. 固有名詞の登録 UI

**ツールバーの「固有名詞」ボタンからドロワーで開く。** 既定は閉じた状態。

①ではなくこの画面に置くのは、このリストを使うのが整文だけだから。使う画面に設定を置く。

2列構成。独立したコンポーネント `GlossaryPanel.tsx`。

| 列 | 内容 | 編集 |
|---|---|---|
| 左 | この会議の固有名詞（`Project.glossary`） | 可 |
| 右 | 全体リスト（`GLOBAL_GLOSSARY`） | 不可（参考表示） |

**左列の操作（実装どおり）**

- 登録済みの語は**一覧表示**し、各行に削除用の × ボタンを置く
- 追加は「まとめて貼り付け」ボタンで開く `textarea` から行う。1行1語で、
  空行と前後の空白は落とす（`parseTerms()`）。既にある語は重複登録しない
- 全体リストに既にある語を入力した場合は、保存はするが「（全体リストに登録済み）」と
  小さく注記する（消しはしない）
- 登録が0件のときは「まだ登録がありません。「まとめて貼り付け」から登録してください。」と表示する

> **既知の不整合**: ①の参加者登録は「テキストエリア1つで追加も修正も削除も行う」形に
> 統一したが、固有名詞はこの旧い形（一覧＋×ボタン＋追加用テキストエリア）のまま
> 残っている。既存の語を直すには「削除してから貼り直す」必要がある。参加者と同じ
> 「テキストエリア1つ」へ寄せるかは未着手。

**右列の表示**

- 読み取り専用の一覧
- 「ここにある語は登録不要です。」と添える

保存は左列を変更するたびに 2 秒デバウンスで走る（第5.3章）。

## 5. 一括変換

### 5.1 挙動

- **既定では未変換の行だけを処理する。** 既に整文結果がある行は飛ばす
- 上書きしたい場合は明示的なチェックボックス（「変換済みの行もやり直す」）を経由させる。
  手動修正済みの行は、このチェックを入れても上書き確認モーダルを通るまで対象に含めない
- 1行ずつ順次処理（並列度1）。同時リクエストを増やしても体感は改善せず、レート制限と
  課金事故のリスクだけが増える
- 1行終わるたびに結果を state に反映し、行の表示を更新する。全部終わるまで画面が固まる
  作りにしない
- 「中断」ボタンで停止する。停止は**実行中の1行が終わってから**効く（`abortRef` をループの
  先頭で見るため）。処理済みの行はそのまま残す

### 5.2 確認モーダル

**AI で既存の内容を上書きする操作には、実行前に全画面モーダルを挟む。** AI はあくまで
補助であり、要約と判断は人が行うという方針による（全体仕様 第1章）。

| 操作 | 表示するモーダル |
|---|---|
| 一括変換（未変換行のみ、通常運用） | 件数確認モーダル |
| 一括変換（「変換済みの行もやり直す」ON かつ手修正済み行あり） | 上書き確認モーダルのみ |
| 個別再変換（対象行が手修正済み） | 上書き確認モーダル |
| 個別再変換（対象行が手修正済みでない） | モーダルなし。即実行 |

対象が0件のときはモーダルも出さず、何もしない。

**文言**（`RefineApp.tsx` の実装どおり）

```
[件数確認モーダル]
○件を一括変換します。よろしいですか？

[上書き確認モーダル・一括]
このうち○件は手動で修正済みです。上書きすると修正内容は失われます。よろしいですか？

[上書き確認モーダル・個別]
この行は手動で修正済みです。上書きすると修正内容は失われます。よろしいですか？
```

**優先順位**

一括変換で両方の条件を満たす場合、上書き確認モーダルだけを表示する。連続して2つ出すと
確認疲れになり、確認の意味が薄れる。上書き確認のほうが情報量が多く、一括変換すること
自体も含意している。

**実装**（`src/components/ConfirmModal.tsx`）

- 「キャンセル」「実行」の2択。`role="alertdialog"` / `aria-modal="true"`
- 背景クリック・Escape キーも「キャンセル」扱い
- 既定フォーカスはキャンセル側（`autoFocus`）。誤って Enter で実行されないようにする
- 上書き確認では「実行」を `btn-danger` にする（`danger` prop）
- `window.confirm()` を使わないのは、ブラウザ標準のダイアログはスタイルを統一できず、
  アプリの一部として見えないため

件数を毎回表示するのは、無意識にボタンを押す抑止のため。

### 5.3 保存

- 1行変換されるたびに `refinements` を更新し、**2秒デバウンス**を挟んで
  `PATCH /api/projects/{id}` へ送る。送るのは `refinements` / `glossary` / `promptPresetId`
- 3列目を人が手で編集した場合も同様。`edited: true` を立てる
- `beforeunload` で引き止め、`pagehide` で `keepalive` 付き送信を行う。300行のループ途中で
  閉じても、再度開けば続きから再開できる

**保存待ちの追い越し**

固有名詞・プリセットはサーバー側でプロジェクトを読み直して組み立てるため、登録・切替の
直後（デバウンス2秒の途中）に変換を始めると保存前の内容が使われる。一括変換・個別再変換の
どちらも、開始前に未保存分を送り切る `flushSave()` を挟んで対処している。

## 6. 個別再変換

各行の2列目の「↻」ボタン。押すとその行だけ再変換する。手修正済みの行では確認モーダルを
挟む（第5.2章）。一括変換の実行中は全行のボタンを `disabled` にする。

失敗した行の復旧もこのボタンから行う（ツールチップが「失敗した行はここから復旧できます」に変わる）。

## 7. 原文のまま確定する操作

3列目の未変換行をクリックして `textarea` を開き、何も編集せずにフォーカスを外すだけで
確定できる（`edited: true`、本文は原文と同一）。専用のボタンは設けない。

「はい」「そうですね」のような整文が不要な発言を、AI に投げずに処理済みにするための経路。
この操作をした行は絞り込みから外れるため、残作業の確認が成立する。

### 誤操作の取り消し

内容を見るだけのつもりでクリックした場合も確定してしまうため、確定直後に
「原文のまま確定しました（取り消す）」を **6秒間**（`UNDO_NOTICE_MS`）表示する。
取り消すと未変換の状態に戻る。

- 対象は未編集のまま確定した場合のみ。1文字でも編集した行では表示しない
- 案内を出したあとでその行を触っていた場合（`updatedAt` が変わっている場合）は、
  「取り消す」を押しても何もしない
- 自動的に消える。永続的なボタンは置かない
- 確定の条件そのものは変更しない。「1文字でも触った場合だけ確定」にすると、整文不要の
  行をクリックだけで処理する経路が失われる

## 8. AI 連携

### 8.1 構成

```
ブラウザ（整文画面）
  ↓ POST /api/refine  { projectId, body, prevBody, nextBody }
Next.js Route Handler（サーバー）
  ↓ Anthropic Messages API  （APIキーは環境変数 ANTHROPIC_API_KEY）
```

- API キーはサーバー側の環境変数に置く。クライアントに渡さない
- `currentUser()` による認証と、`loadOwned()` による所有者チェックを必ず通す
- **固有名詞・参加者・プリセットはリクエストで受け取らず、サーバー側でプロジェクトを
  読み直して組み立てる。** クライアントから差し替えられないようにするため
- Anthropic API の呼び出しは `src/lib/refine.ts` の `refine()` に閉じる。後から他の
  モデルへ差し替えられるようにしておく

### 8.2 モデル

`REFINE_MODEL` 環境変数で指定。既定は `claude-sonnet-5`。

**Haiku 4.5 を採用しなかった理由**

実データで比較したところ、Haiku は読みやすい代わりに情報を落とした。

- 「その上に校長先生からの許可というところはある」（上位承認の存在）が消えた
- 「琉大附属中とか琉大の敷地外とか」の具体性が「学校敷地外」に丸められた
- 段落の再構成が入り、「論点を再構成しない」の境界に踏み込んだ

Sonnet 5 はほぼ原文の情報を保つ。議事録としてはこちらが正しい挙動。

宛先 URL は `REFINE_API_URL` で差し替えられるが、これは e2e テストでスタブへ向けるための
ものであり、本番では設定しない。

### 8.3 `max_tokens`

**8192。** 当初 1024 だったが、4,000字規模の発言で出力が上限に達し、文の途中で切れた
結果がそのまま保存される事故が起きた。

### 8.4 リクエストに含める情報

| 項目 | 用途 | 置き場所 |
|---|---|---|
| 整文の方針（定義・やらないこと・プリセットの `endingPolicy`） | 整文の指示 | system |
| 固有名詞リスト | 組織名等の保護。全体リストと会議固有リストを結合（全体仕様 第5章） | system |
| 参加者リスト（`所属/氏名`） | 人名の誤変換防止 | system |
| 対象の発言本文 | 整文対象 | user |
| 前後1行の本文 | 指示語・省略された主語の解決。**参考情報であり変換対象ではない**ことを明示 | user |

前後1行は、**議題見出しを除いた発言ブロックの並び**（`utteranceBlocks`）での前後を取る。
先頭・末尾では「（なし）」を入れる。

### 8.5 プロンプトの構成

`buildSystemPrompt()` が system を、`buildUserPrompt()` が user を組み立てる。
プロジェクト単位で固定される内容（方針・固有名詞・参加者）は system に、発言ごとに
変わる内容（対象・前後1行）は user に置く。

**system の構成**

```
## 整文の定義
　行うこと（フィラー除去・言い淀み統合・冗長圧縮 + プリセットの endingPolicy）
　行わないこと（全体仕様 第2章の一覧）
## 出力形式
## 前後の発言について
## 固有名詞リスト（表記を変更しないこと）
## 参加者リスト（人名の変換に注意）
```

**前置きの抑止**

「## 出力形式」で「整文後のテキストのみを出力する。前置き・説明・引用符・見出しは一切
付けない」と指示する。

assistant prefill は使わない。**Claude Sonnet 5 / Opus 5 / 4.6 以降では廃止されており、
送ると 400 が返る。** コードとフラグは削除済み。

**プロンプトキャッシュ**

system に `cache_control: { type: "ephemeral" }` を付けているが、system が1,000トークン
前後で最小キャッシュ長に届かない可能性がある。届かない場合もエラーにはならず素通りする
ため実害はない。実運用で `usage.cache_read_input_tokens` を見て判断する
（**現状コードは `usage` を読んでいない**。全体仕様 第6.4章）。

### 8.6 エラー処理

| 状況 | ステータス | ループの挙動 |
|---|---|---|
| 利用上限到達・レート制限 | 429 | 即座に停止・リトライなし |
| サーバー一時障害 | 5xx | 1回だけリトライ、それでも駄目なら失敗にして次へ |
| ネットワーク障害（応答なし） | なし | 5xx と同じ（1回だけリトライ） |
| `stop_reason: "max_tokens"` | 422 | リトライなしで即座に失敗にして次へ |
| `ANTHROPIC_API_KEY` 未設定 | 500 | 5xx と同じ扱いになるため、全行が2回ずつ失敗する |

`RefineRequestError.isRateLimited` / `.isRetryable`（`src/editor/refineClient.ts`）が
この分岐を持つ。リトライ中に「中断」が押された場合は、リトライせずに抜ける。

**429 でリトライしない理由** … 上限に達している可能性があるため、叩き続けると状況が
悪化する。停止時はバナーに「レート制限または利用上限に達したため中断しました。
しばらく待ってから再開してください。」と出す。

**422 を別カテゴリにした理由** … `stop_reason: "max_tokens"` は HTTP 200 で返るため
`!res.ok` 判定をすり抜ける。`refine()` 内で明示的にチェックして `RefineError` を投げる。
同じ発言を再送しても同じ長さで打ち切られるため、5xx のような一時的障害ではなくリトライしない。

**切れた結果を保存しない理由** … 出力が自然な日本語のまま途中で終わるため、保存すると
利用者が欠落に気づけない。失敗扱いにすれば個別再変換から復旧でき、少なくとも気づける。

失敗理由はツールバー下のバナー（`.refine-error-note`）に表示する。理由が分からないまま
「失敗」だけ並ばないようにするため。

### 8.7 課金の上限設定

Anthropic Console で月次の利用上限を設定しておく。プリペイド式のため、自動チャージを
オフにすればクレジット残高が事実上の上限にもなる。上限到達時は API が 429 を返す。

想定規模（7会議 × 300行程度）では月あたり数ドル未満の見込み。
