# 議事録エディタ（speaker-tagger）

WhisperX の文字起こし（単語単位タイムスタンプ付き）を、
**話者ごとに整理された表**に仕上げるための編集ツールです。
最後は表をコピーして Word などに貼り付けて使います。

- 上：ツールバー（2段構成）
  - 1段目 … 「← 一覧」／画面間ナビ（話者整理・整文・出力）／議事録名／
    「取り込み・参加者」／「使い方」。**いま何を開いているか**を示す段です
  - 2段目 … 保存状態／ブロック数と未割り当て件数／「次の未割り当てへ」／
    ペイン切替／「⇅ 連動」／文字サイズ。**この画面の作業状態と表示の制御**です。
    背景をわずかに暗くして1段目と区別しています（下に境界線を1本）
- 左：生テキストの編集（`@` 話者 / `--` 区切り / `#` 議題見出し）
- 右：それをそのまま反映した表（話者・発言内容）
- 下：音声を聞きながら編集するための再生バー

議事録作成は3画面に分かれています（タブではなく別 URL）。

| # | 画面 | URL | 役割 |
|---|---|---|---|
| ① | 話者整理画面 | `/projects/{id}` | 発言の区切り・話者の割り当て・誤字修正（本 README の対象） |
| ② | 整文画面 | `/projects/{id}/refine` | 口語の簡素化・体言止め化 |
| ③ | 出力画面 | `/projects/{id}/export` | 列を選んで Word 用にコピー |

①②③は相互に行き来でき、各画面上部の共通ナビゲーションとプロジェクト一覧の
各行から直接遷移できます。

## できること

| | |
|---|---|
| 取り込み | WhisperX（`segments[].words[]`）の JSON。pyannote の話者ラベルがあれば参考情報として使う |
| 話者付け | 事前登録した参加者を `@` で選ぶ。候補は直近に使った人が先頭（MRU） |
| 区切り | `--` の行が発言の区切り。編集画面では区切り線として表示 |
| 議題 | `#` で始まる行は議題見出し。表では列をまたぐ行になる |
| 時刻 | 表の1列目に常時表示。区切り記号 `--@12.3` が持つ実測値で、文字数比での按分はしない |
| 音声 | 時刻クリックでその位置から再生。再生位置に応じて該当ブロックを自動ハイライト。速度変更あり |
| 連動 | 左右のスクロールが連動。ブロック（表の1行）を目印にするので、左右の高さが倍近く違っても同じ発言が並ぶ |
| 進捗 | 「全◯ブロック中、話者未割り当て◯件」と、次の未割り当てへ飛ぶボタン |
| 保存 | 自動保存。画面上に「保存済み / 未保存の変更あり」を常時表示 |
| 取り消し | ブラウザ標準の `Ctrl+Z` / `Ctrl+Shift+Z`。ボタン操作で入れた区切りや話者も戻せる |
| 出力 | ③出力画面で列構成を選んで「表をコピー」。Word に貼ると表として認識される |
| 整文 | ②整文画面で、口語をAIで整えられる（現状はダミー。第7章のAPI連携は未実装） |
| 固有名詞 | ①のドロワーで会議固有の語を登録。整文時に変更されないよう保護される |
| 使い方 | 画面右上の「使い方」ボタンから、操作説明とショートカット一覧をいつでも呼び出せる |

複数人で使えますが、**データはユーザーごとに完全に分かれます**（共同編集はしません）。

## 動かす

```bash
npm install
npm run dev          # http://localhost:3000
```

初回は画面右上の「新規登録」からユーザーを作ります。
保存先は既定でプロジェクト直下の `.data/`（JSON ファイル）です。

本番相当で動かす場合:

```bash
npm run build
npm start
```

### 環境変数

| 変数 | 用途 |
|---|---|
| `APP_SECRET` | ログインセッションの署名鍵。**本番では必ず設定してください**（未設定だと保存先に自動生成した鍵を置きます） |
| `KV_REST_API_URL` / `KV_REST_API_TOKEN` | Vercel KV を使う場合 |
| `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` | Upstash Redis を使う場合 |
| `DATA_DIR` | ファイル保存先を変えたいとき（既定 `.data`） |

KV 系の変数が設定されていればそちらを、なければファイル保存を使います。

## デプロイ（Vercel の無料枠を想定）

Vercel などのサーバーレス環境はファイルシステムに書き込めないため、
**KV の設定が必須**です。

1. リポジトリを Vercel にインポート（設定は既定のままで動きます）
2. Storage から KV（Upstash Redis）を作成し、プロジェクトに接続
   → `KV_REST_API_URL` / `KV_REST_API_TOKEN` が自動で入ります
3. 環境変数に `APP_SECRET` を追加（`openssl rand -hex 32` などで生成）
4. デプロイ

Netlify / Cloudflare Pages / 自前サーバーでも、上記の環境変数を渡せば同じように動きます。

### 音声ファイルの置き場所

**音声はサーバーへ送信しません。** ブラウザの IndexedDB に保存します。

会議の録音は数十〜数百 MB になり、無料枠の KV やデータベースには載りません。
テキストと編集結果はサーバーに保存されるので他の端末からも続きを編集できますが、
音声は取り込んだブラウザでのみ再生できます（別の端末では音声を選び直してください）。

## 書き方

```
# 議題1 開会について
@●●小/太田 おはようございます。
本日はよろしくお願いします。
--@12.3
@県教委/山田 ありがとうございます。
--@18.6
```

- `@` を打つと参加者の候補が出ます。↑↓ で選び Enter で確定
  - 候補は**事前登録した参加者だけ**。所属＋氏名で区別するので、同姓の方がいても取り違えません
  - 行末で確定すると改行、発言の途中に差し込んだ場合は空白が入ります
- `--` だけの行が発言の区切り（1 ブロック = 表の 1 行）
- `--@12.3` の数字は、そのブロックが音声の何秒から始まるかです。
  取り込み時に自動で付き、表の「時刻」列と再生の連動に使われます。
  本文を編集しても時刻はずれません（区切りごと消したときだけ無くなります）。
  手で書き足すこともできます。時刻の無い `--` もそのまま使えます
- `#` で始まる行は議題見出し。話者は持ちません
- 発言の中の改行はそのまま表のセル内に残ります（箇条書きが崩れません）
- **発言が重なっている箇所**は、`--` で行を割って別々に話者を付けてください。
  1 つのブロックに `@` を 2 つ書けば「A / B」と並べて表示することもできます

### 左右のスクロール連動

既定でオンです（画面右上の「⇅ 連動中」で切り替え、設定は保存されます）。

左右のペインは行の折り返し方が違うため、高さが倍近く変わります。
そのため画素やスクロール率では対応づけできません。
代わりに **ブロック（＝表の1行）を共通の目印**にして、
「上端に見えているのは何番のブロックの何割の位置か」を移し替えています。
ブロックの中も割合で補間するので、長い発言の途中でスクロールしても
もう片方が止まったままになりません。

表の行をクリックしたとき、未割り当てへジャンプしたとき、
音声の再生に追従するときは、両方のペインがその発言へ揃います。

### pyannote の話者推定の扱い

自動の話者分離は**確定情報として使いません**。
話者が切り替わったと判定された位置に、編集画面で**オレンジの点線**を表示するだけです。
実際の話者は人が `@` で決めます。

取り込み時のチェックを外さなければ、点線の位置にあらかじめ `--@秒` を入れた状態で始められます
（不要なら結合し直せます）。精度が低いと感じたらチェックを外して取り込んでください。

### 固有名詞の登録

①のドロワー内、参加者登録の下に「固有名詞の登録」があります。

- 左列：この会議だけに出る固有名詞（議案名、来賓の所属等）。1行1語で
  まとめて貼り付けられます
- 右列：どの会議にも出る可能性がある語（アプリに同梱、`src/lib/glossary.ts`）。
  参考表示のみで編集はできません
- 登録した語は、②の整文画面で AI に「変更しないこと」として渡されます
  （左列＋右列を結合したものを使用）
- 右列に既にある語を左列に登録しても保存はされますが、「全体リストに
  登録済み」と注記が付きます（消えません）

### 整文画面（②）

`/projects/{id}/refine`。話者整理画面で確定した発言を、口語から
読める文章へ整える画面です。

- 1発言 = 1行。フィラーの除去、語尾の簡素化などを AI に行わせます
  （**現時点では Anthropic API を呼ばず、ダミーの文字列を返しています**。
  実際の API 連携は今後の対応です）
- 話者整理画面で行を挿入・削除しても、本文が変わっていない行の整文結果は
  保持されます（本文のハッシュをキーにしているため）

**3列目は「その行が実際に出力される内容」です。**上段に話者とステータス、
下段に本文を置いています。整文結果がまだ無い行も空欄にはせず、
実際に出力される原文を薄いグレーで表示します。濃いか薄いかで
AI を通ったかどうかが分かります。

| ステータス | 意味 | 下段の表示 |
|---|---|---|
| 原文のまま出力 | 整文結果が無い。出力では原文がそのまま使われる | 原文（薄いグレー） |
| 変換中 | 変換の実行中 | 原文（薄いグレー） |
| AI変換済み | AI が整文した（人は触っていない） | 整文後のテキスト |
| 手修正済み | 人が手で直した。AI の上書きから保護される | 整文後のテキスト |
| 失敗 | 変換に失敗した。↻ で復旧できる | 原文（薄いグレー） |

- 薄いグレーの原文を**クリックすると編集できます**。原文が入った状態で
  始まるので、**何も直さずにフォーカスを外すだけで「手修正済み」として
  確定**できます。「はい」「そうですね」のような整文が不要な発言を、
  AI に投げずに処理済みにするための操作です
  - 見るだけのつもりでクリックした場合に備えて、確定した直後だけ画面下部に
    「原文のまま確定しました（取り消す）」が出ます。取り消すと確定前
    （＝原文のまま出力）に戻ります。この案内は数秒で自動的に消えます
  - 1文字でも編集した場合は通常の「手修正済み」として扱い、この案内は出ません
- 「一括変換」は既定で「原文のまま出力」の行だけを処理します。
  「変換済みの行もやり直す」にチェックすると変換済みの行も対象になりますが、
  手で直した行は対象に含める前に確認を求めます
- 各行の再変換ボタン（↻）で1行だけやり直せます。手修正済みの行では
  確認を挟みます
- 上部の「表示」で**「原文のまま出力」の行だけに絞り込めます**。
  3列目が常に埋まっているため、スクロールして残作業を数えることができません。
  絞り込んで0行になることをもって、処理漏れが無いことを確認します
- 変換結果は2秒のデバウンスを挟んで自動保存されます。ブラウザを閉じても
  失われず、続きから再開できます
- 議題見出し（`#`）は整文の対象外です

### 出力画面（③）

`/projects/{id}/export`。完成した議事録の表を、列構成を選んで Word へ
コピーする、読み取り専用の画面です（編集はできません）。

- 表示オプションは画面上部で切り替えます。選択内容はユーザーごとに保存され、
  次回も同じ設定で開きます

  | オプション | 選択肢 | 既定 |
  |---|---|---|
  | 時刻列 | 含める / 含めない | 含めない |
  | 話者列 | 含める / 含めない | 含める |
  | 発言内容 | 整文後 / 原文 | 整文後 |

- 「整文後」を選んだとき、整文結果がまだ無い行は原文がそのまま使われます
  （空セルにはなりません）。②の3列目に表示されている内容が、そのままここに出ます
- 「原文のまま出力」の行が何行あるかを画面上部に表示します。②で処理漏れが
  あった場合に、コピーする前に気づけるようにするためです
- 「表をコピー」は①の表形式ビューには無く、この画面に一本化されています
  （①はあくまで話者割り当ての確認用です）

### 時刻の求め方

**時刻はブロック自身が持ちます。** 区切り記号に `--@12.3` の形で書き込まれており、
表示や連動のたびに引き直すことはありません。

- 取り込み時、各セグメントの先頭単語の実測値を区切りへ書き込みます
- `Alt` + `D` で区切りを入れたときは、その瞬間に一度だけ単語データを引いて
  カーソル位置の時刻を求め、区切りへ焼き付けます
- 再生位置に対応するブロックは「時刻が再生位置以下である最後のブロック」です。
  時刻を持たないブロックは連動の対象外として飛ばします（時刻列は空欄）

文字数比などによる按分は一切していません。また、再生位置から単語データと
文字オフセットを経由してテキスト位置を逆引きすることもしていません。
逆引きは本文を編集した時点で対応が崩れるため、ブロックを削除すると
ハイライトが無関係な位置へ飛んでいました。

単語データ（`ProjectWords`）はブロックを分割する瞬間の時刻取得と、
pyannote の話者交代ヒントの位置合わせに使っています。

## ショートカット

画面右上の「使い方」ボタンからも、この一覧（7項目）と操作説明を見られます。
アプリ内のモーダルには、専用のボタン・表示が既にあるもの
（ペイン表示切替・文字サイズ・スクロール連動）は載せていません。

| キー | 動作 |
|---|---|
| `Space` | 再生 / 一時停止（編集中は空白の入力になります） |
| `Shift` + `Space` | 編集中でも再生 / 一時停止 |
| `Alt` + `←` / `→` | 3 秒 戻す / 進める |
| `Alt` + `↑` / `↓` | 再生速度 |
| `Alt` + `J` | 未割り当ての次の箇所へ |
| `Alt` + `D` | カーソル位置に区切り `--`（その位置の時刻が付きます） |
| `Alt` + `A` | 話者を選ぶ（`@` を入力） |
| `Ctrl` + `Z` / `Ctrl` + `Shift` + `Z` | 取り消し / やり直し |

このほか、`Alt` + `1`/`2`/`3`（左のみ / 両方 / 右のみ）、
`Alt` + `-`/`=`（文字サイズ）、`Alt` + `S`（スクロール連動切替）も使えます。
これらは画面上に対応するボタン・表示があるため、アプリ内のモーダルには載せていません。

## テスト

型チェックと、実際のブラウザ（Chromium）でのひととおりの操作確認の両方があります。

```bash
npm run typecheck
npm run build
npm run test:e2e
```

- `tests/sourceKey.test.mjs` … ブラウザ不要。本文が同じなら同じキー、違えば違うキーになること
- `tests/normalizeProject.test.mjs` … ブラウザ不要。`refinements`/`glossary` が無い既存データを壊さず読めること
- `tests/editor.test.mjs` … 取り込み、`@` サジェスト、区切り、見出し、表、取り消し
- `tests/audio.test.mjs` … 再生・シーク・追従ハイライト・ショートカット、音声がサーバーへ送られないこと
- `tests/scrollsync.test.mjs` … 左右で高さが 1.8 倍違う状態でも、上端に同じ発言が来ること
- `tests/nav.test.mjs` … ①②③の3 URL が相互に行き来でき、ブラウザの戻るも効くこと
- `tests/refinements.test.mjs` … `Project.refinements`/`glossary` の保存・読み込み（API レベル）
- `tests/glossary.test.mjs` … 固有名詞の登録・重複注記・全体リストの参考表示・保存
- `tests/refine.test.mjs` … 整文画面のステータス遷移・一括変換・中断・再開・保存、確認ダイアログ、絞り込み、原文のまま確定
- `tests/export.test.mjs` … 出力画面の列の出し分け・整文後/原文の切替・コピー・設定の保存
- `tests/isolation.test.mjs` … 他ユーザーのデータに触れないこと（新設の②③も含む）
- `tests/performance.test.mjs` … 1 時間規模（約 2,500 発言・2 万語）での入力の重さと時刻の正しさ

テスト用の入力ファイルは `tests/fixtures.mjs` が生成します（リポジトリには含みません）。
Chromium の場所は `CHROMIUM_PATH` で指定できます。

## スコープ外（意図的に入れていないもの）

- 会議ヘッダ（会議名・日時・出席者・議題一覧）の入力と管理
- Word ファイルの自動書き出し（表をコピーして貼り付ける前提）
- 共同編集
- 整文（②）の Anthropic API 連携（現状はダミー文字列。今後の対応）
