## 1. 画面の役割

左ペインで生テキストを編集し、右ペインに表を表示する2ペイン構成。

| 記法 | 意味 |
|---|---|
| `@所属/氏名` | 話者の指定（事前登録した参加者だけ。第4章） |
| `--` | 発言の区切り（`-` が2つ以上の行。前後の空白は無視） |
| `--@時刻` | 時刻付きの区切り。時刻は秒・分:秒・時:分:秒のどれでも書ける（第6章） |
| `#` | 議題見出し（行頭の `#`。話者を持たない見出し専用のブロック） |

区切りと区切りの間（区切りが無ければ先頭から）が1ブロック＝表の1行になる。
**1ブロック = 話者1人**を原則とする（第4.2章「発言が重なっている箇所」）。

音声を聞きながら編集できるよう、タイムスタンプと連動再生する機能がある。音声はサーバーに
送らず、ブラウザの IndexedDB に保存する（第7章）。テキスト（`rawText`・参加者・メモ）は
サーバー側の KV に保存される（全体仕様 第4.1章）。

### この画面で確定させること

後続の工程は、この画面の出力を確定済みとして扱う。

- 発言の区切り位置
- 話者の割り当て
- **固有名詞・誤変換の修正** … ②の整文では推測による修正を一切行わないため、
  ここで直さなければ誤ったまま出力される

## 2. ツールバー

情報を「どこにいるか」と「今の作業状態」で2段に分ける。

| 段 | class | 内容 |
|---|---|---|
| 1段目 | `.topbar-main` | 画面間ナビ（`ProjectNav`：「← 一覧」と「① 話者整理」「② 整文」「③ 出力」の番号付きボタン）／ 議事録名の入力欄 ／（右寄せ）「取り込み・参加者」（開いている間は「設定を閉じる」）／「使い方」 |
| 2段目 | `.topbar-sub` | 保存状態 ／「全 ○ ブロック中、話者未割り当て ○ 件」／「次の未割り当てへ」／（右寄せ）ペイン切替（左・両方・右）／「⇅ 連動中」（オフのときは「⇅ 連動オフ」）／ 文字サイズのスライダー |

- 1段目と2段目は背景の濃淡で区別する。2段目に `--panel-sub` を敷き、下に境界線を引く。
  **色相は変えない。**「保存済み」バッジや未割り当て件数の色が埋もれるため
- 画面間ナビの現在地（この画面では「① 話者整理」）はリンクにせず、選択中の見た目
  （薄い背景＋太字）で示す（全体仕様 第3章）
- ログインユーザー名はこの画面には表示しない（プロジェクト一覧にある。ログアウトも一覧側）
- 議事録名は1段目の入力欄で直接編集する（自動保存の対象。空にして保存すると元の名前のまま）
- 「⇅ 連動中」は「両方」表示のときだけ押せる
- 保存状態の表示は「保存済み」「未保存の変更あり」「保存中…」「保存できませんでした」

### 保存

`title` / `rawText` / `participants` / `mru` / `audio` を **900ms デバウンス**で
`PATCH /api/projects/{id}` へ送る（②は2秒。こちらは打鍵のたびに走るため短くしてある）。
`memo` は変更したときだけ同じ PATCH に含める（第11章）。
`beforeunload` で引き止め、`pagehide` で `keepalive` 付きの送信を行う。

音声をブラウザへ保存している間も `beforeunload` で引き止める（第7章）。

表示設定（`UserSettings`）は 400ms デバウンスで `PATCH /api/settings` へ別に送る
（`pagehide` でも `keepalive` 付きで送る）。送るのはこの画面の表示設定（`fontSize` /
`paneMode` / `playbackRate` / `followPlayback` / `syncScroll`）だけ。サーバーは送られた
キーだけを既存の設定に重ねるので、③専用の設定（`exportIncludeTime` など）やメモの開閉
（`memoOpen`）を古い値で上書きしない。

## 3. 「取り込み・参加者」ドロワー

1段目の「取り込み・参加者」で開閉する。**未取り込みのプロジェクトでは既定で開く**
（`useState(!project.imported)`）。

上段を2列にする。左列に手順リスト、右列に JSON 取り込みエリア。その下に参加者の登録。

手順リストは4項目。1〜3は済んだら番号の代わりに ✓ が付く。

1. WhisperX の JSON を取り込む（取り込み済みなら ✓）
2. 参加者を登録する（1名以上いれば ✓）
3. 音声ファイルを取り込む（任意。このブラウザで再生できる状態なら ✓ とファイル名・サイズ）
4. 左側で `@` 話者、`--` 区切り、`#` 議題見出しを付けていく。Word へのコピーは③から

「自動話者分離の切れ目に `--` をあらかじめ入れる」のチェックボックス（既定オン）は、
見出しの横ではなくドロップエリアの直上に1行で置く。見出しの横だと折り返して崩れる。

固有名詞の登録はここに置かない（②の整文画面にある）。使う画面に設定を置く。
音声ファイルを選ぶボタンもここには無く、画面下端の音声バーにある（第7章）。

## 4. 参加者と `@` メンション

### 4.1 参加者の登録

**テキストエリア1つに統一する。** 個別の入力欄グリッド、各行の × ボタン、
「＋1人追加」「まとめて貼り付け」等のボタンは置かない。

- 1行1人。テキストエリアの内容がそのまま参加者リストになる。行を消せばその参加者も消える
- 高さは `rows={10}` で固定し、超えたら内部でスクロールさせる。参加者が30名でも
  パネルの高さが変わらないようにするため
- 解析は `parseBulk()`（`/`／全角スラッシュ／タブ／半角・全角スペースで区切り、最初の
  かたまりを所属、残りを氏名とする）。区切りが無い行は氏名だけの参加者になる
- **確定はフォーカスが外れた時点**（`onBlur`）。入力のたびに解析すると、途中の文字列で
  参加者が登録される
- 打った内容は整形し直さない（「●●小 太田」を「●●小/太田」に書き換えない）
- 下に「○名 登録済み」（確定済みの件数）と、「所属・氏名を変更すると、既にその人に
  割り当てた `@` は外れます」を表示する

#### `id` の扱い

確定時に、`participantLabel`（`所属/氏名`。所属が無ければ氏名だけ）が変わっていない人の
`id` を `keepIds()` が引き継ぐ。同一ラベルが複数ある場合は上から順に割り当てる。

`id` を毎回振り直してもメンションは壊れないが、**MRU（直近に使った話者）が `id` で
紐づいているため、テキストエリアを触るたびにリセットされる。**

#### メンションとの関係（既知の制約）

`@` メンションは `rawText` に `@所属/氏名` という文字列として保存されており、
`parseDoc()` がラベル一致で照合している。`id` は `rawText` に現れない。

したがって所属・氏名を変更すると、`rawText` 内の古いラベルは一致しなくなり、その人に
割り当てたメンションは未割り当てに戻る。自動置換は行わず、注意書きの表示にとどめる。

### 4.2 `@` の解釈

- 話者として扱うのは**事前登録した参加者だけ**。長いラベルから順に照合するので、
  「●●小/太田」と「太田」を取り違えない
- 登録されていない `@` は話者として拾わない。日本語は語の切れ目に空白が無いため、
  当てずっぽうに拾うと一文まるごと氏名になってしまう。印（薄いオレンジの背景）だけ
  付けて本文として残し、打ち間違いに気づけるようにする
- メンション直後の空白1つは本文から落とす

#### 発言が重なっている箇所

`--` で行を割り、別々のブロックにしてそれぞれ話者を付ける。

1つのブロックに `@` を2つ書いて「A / B」と重ねて表示する使い方は**廃止した**。
話者列・本文列とも2人分が連結され、どちらの発言か分からなくなるため。
区切りを入れ忘れて同じブロックに `@` が2つ入った場合は、表の話者列に「A / B」と
連結されて出る（意図した表示ではないので、`--` を入れて分ける）。

### 4.3 話者ピッカー（`@` で開く候補）

`@` を打つと、カーソル位置の下に参加者の候補（`.suggest`）が開く。実装は `RawEditor.tsx`。

**候補**

- 出るのは事前登録した参加者だけ。並びは MRU（直近に使った順）→ 登録順
- `@` に続けて打った文字で絞り込む（ラベル・氏名・所属のいずれかに部分一致。英字の大小は区別しない）
- 参加者が0人のときは開かない。一致する人がいないときは「一致する参加者がいません。
  上の「参加者」から登録してください。」と出す
- `@` から空白・改行をまたぐ、または `@` から30文字を超えると、メンション入力とは
  みなさない（閉じる）
- 区切り行の時刻（`--@12.3`）の `@` では開かない。矢印キーで区切り行を通過しただけで
  開き、上下キーを候補選択に取られて本文へ戻れなくなるため

**開く・閉じる**

- **開くのは文字を入力したとき（IME の確定を含む）だけ。** 矢印キー・クリック・Home/End
  などのカーソル移動では、閉じることはあっても開かない。カーソルが `@所属/氏名` の直後や
  途中に来るたびに開き、上下キーを取られて本文へ戻れなくなる不具合があったため
- 入力以外でカーソルが動いたら閉じる。同じ `@…` の中での移動でも閉じる。開いたままだと、
  移動先で Enter を押したときにそこで候補が確定してしまうため
- `Escape` で閉じる。閉じた書きかけの `@…` は未登録の `@` と同じく本文として残り、
  同じ `@` に続けて文字を打っても開き直さない（カーソルがその `@` から離れたら解除）
- テキストエリアからフォーカスが外れたら閉じる

**操作**

- `↓` / `↑` で候補を移動する（端まで行くと反対側へ回る）。選択中の候補が枠（最大 260px）の
  外に出たら、枠の中をスクロールする
- `Enter` または `Tab` で確定。マウスでのクリックでも確定できる（ホバーで選択が移る）
- IME で変換中のキー（変換確定の Enter など）は IME に任せ、候補の操作に使わない
- **安全策:** キーを押した時点で、カーソルが候補を開いた位置から動いていたら（マウス・
  トラックパッド・IME などで上の「閉じる」処理をすり抜けた場合）、Enter や ↑↓ を候補の
  操作に使わず、閉じて普通のキーとして通す。通すと `@` から今のカーソル位置までが候補で
  上書きされてしまうため

**開いた瞬間のスクロール**

画面の下のほうで `@` を打つと候補がはみ出すため、開いた瞬間に**1回だけ**、候補全体が
見えるまで左ペインをスクロールする。入力中の行（候補の上端）が画面上端より上へ行くほどは
動かさない。絞り込みで候補が変わって再描画されても、再スクロールはしない。

**確定時の挿入**

`@所属/氏名` を入れたあと、**無条件で改行を入れる**（1ブロック = 話者1人を徹底するため）。
ただしカーソル直後の1文字がすでに改行なら、それ以上は足さない（話者を付け替える場面で
空行が増えないようにする）。確定した参加者は MRU の先頭へ移る。

区切り（`--`）は自動では入れない。話者が替わる箇所の区切りは `Alt` + `D` で人が入れる。

`tests/picker.test.mjs` がこれらの操作を、`tests/editor.test.mjs` が確定時の改行を検証している。

## 5. JSON の取り込み

WhisperX の出力 JSON（`assign_word_speakers()` の戻り値をそのまま `json.dump()` したもの）を
受け付ける。実装は `src/editor/whisperx.ts` / `ImportPanel.tsx`。

### 期待する構造

```json
{
  "segments": [
    {
      "text": "おはようございます",
      "start": 12.3,
      "end": 13.1,
      "speaker": "SPEAKER_00",
      "words": [
        {"word": "おはよう", "start": 12.3, "end": 12.8, "speaker": "SPEAKER_00"},
        {"word": "ございます", "start": 12.8, "end": 13.1, "speaker": "SPEAKER_00"}
      ]
    }
  ],
  "language": "ja"
}
```

### 読み取り仕様

- 最優先で `segments[].words[]` を読む。無ければ `word_segments`、それも無ければ
  セグメント単位にフォールバック
- 単語のキーは `word` でも `text` でも可
- 話者は単語単位の `speaker` を優先し、無ければセグメントの `speaker` を使う
- 話者が特定できない場合もエラーにはならない
- 単語が1つも取れなければ「単語データが見つかりませんでした。WhisperX の出力 JSON か
  ご確認ください。」、JSON として読めなければ「JSON として読み取れませんでした。
  ファイルをご確認ください。」
- `language` キーは読み込み時に使用していない
- **単語単位のタイムスタンプが重要。** 人手でどこを分割しても、その位置の単語が持つ
  実際の時刻を使うため（第6章）。文字数比での按分は行わない
- 取り込み後に「単語 ○ 件 / セグメント ○ 件 / 自動判定された話者 ○ 名 / 長さ ○」を表示する。
  単語単位のタイムスタンプが無いときはその旨を添える

取り込むと左ペインの本文は**取り込んだ内容で置き換わる**（取り込み済みのプロジェクトでは
ドロップエリアにその旨を表示する）。各セグメントの本文を1行ずつ並べたものが初期テキストになる。

保存は `PUT /api/projects/{id}/words`（単語列は `p_{id}_words`、本文と `hints` は
`Project` 本体。`imported` はサーバー側で `true` にする）。

### 自動話者分離の位置づけ

**確定情報として使わない。**

- 発言が重なることが多く、自動判定の精度には期待していない
- 単語の話者ラベルが切り替わった位置を `hints` として保存し、編集画面で
  **オレンジの点線**（縦線）を表示するだけ。幅ゼロなので本文の行送りは変わらない
- 実際の話者名は、人が事前登録した参加者リストから選んで確定させる

pyannote に求めているのは「話者が変わった可能性がある」という参考情報であり、
正確な話者特定ではない。

取り込み時のチェック（「自動話者分離の切れ目に `--` をあらかじめ入れる」）がオンなら、
**セグメントの話者が前のセグメントから替わったところ**に、そのセグメントの先頭単語の時刻を
付けた区切り（`--@12.34` の秒表記。0.01秒単位）を入れた状態で始められる。点線は単語単位、
この区切りはセグメント単位なので、位置が一致しないことがある。精度が低いと感じたら
チェックを外して取り込む（区切りも時刻も入らない）。

## 6. 時刻

**時刻はブロック自身が持つ。** 直前の区切り記号に `--@時刻` の形で書き込まれており、
表示や連動のたびに引き直すことはしない（`Block.time`）。

### 6.1 区切りに書ける時刻の表記

`parse.ts` の `separatorTime()` が次のいずれも読み取る（再生バーや表の「時刻」列の表示を
そのまま写して書けるようにするため）。

| 表記 | 例 | 主な入り方 |
|---|---|---|
| 秒 | `--@83.5` | JSON 取り込み時に自動で付く（0.01秒単位） |
| 分:秒 | `--@1:23` / `--@1:23.5` | 手で書き足すとき |
| 時:分:秒 | `--@0:01:23` / `--@1:02:03` | `Alt` + `D` で入る形。1時間を超える会議でも同じ |

- 分・秒の桁は 0〜59。`--@1:75` のような値は時刻として読まない（その行は区切りとしても
  扱わず、本文になる）
- `--` と `@` の間、`@` と数字の間の空白は許す
- 時刻の無い `--` の次のブロックや先頭のブロックは時刻を持たない（`null`）。前のブロックの
  時刻を引き継がない
- 区切りの直後に議題見出しを挟んでも、時刻は見出しの次の発言に付く

### 6.2 区切りを入れたときの時刻（`Alt` + `D`）

カーソル位置に区切り行を入れ、その瞬間に一度だけ時刻を決めて**時:分:秒**の形で焼き付ける
（`separatorLine(time, "hms")`。時は 0 でも省かず、秒は切り捨て。例 `--@0:01:23`）。

1. 音声が読み込まれていて再生位置が 0 より後なら（再生中・一時停止中・頭出し後）、
   **再生位置の2秒前**を使う（`PLAYHEAD_LEAD = 2`。0秒より前にはしない）。話者が替わった
   のを聞いてから押すため、再生位置は発言の頭より遅れている
2. それ以外は、カーソル位置の単語データから引いた時刻を使う。単語データの時刻は発言の
   頭そのものなので、**ずらさない**
3. どちらも取れなければ時刻なしの `--` になる

カーソルが行の途中にあれば、改行してから区切り行を入れる。ボタン「-- 区切り」も同じ動作。

### 6.3 表示と連動

- 表の「時刻」列には `M:SS`（1時間以上は `H:MM:SS`）で常時表示する。時刻を持たない
  ブロックは空欄。音声があるときは時刻をクリックするとその位置から再生する
- 再生位置に対応するブロックは「時刻が再生位置以下である最後のブロック」
  （`blockAtTime()`）。時刻を持たないブロックは連動の対象外として飛ばす
- 本文を編集しても時刻はずれない。区切りごと消したときだけ無くなる

文字数比などによる按分はしていない。また、再生位置から単語データと文字オフセットを
経由してテキスト位置を逆引きすることもしていない。逆引きは本文を編集した時点で対応が
崩れ、ブロックを削除するとハイライトが無関係な位置へ飛ぶため。

単語データ（`ProjectWords`）は、`Alt` + `D` で再生位置が無いときの時刻取得と、pyannote の
話者交代ヒントの位置合わせにだけ使う。

`tests/separator.test.mjs` が表記の読み取りを、`tests/separatorkey.test.mjs` が `Alt` + `D`
の時刻を検証している。

## 7. 音声

### 7.1 置き場所

**音声ファイルの本体はサーバーに送らない。** ブラウザの IndexedDB（データベース名
`speaker-tagger-audio`、ストア `files`、キーはプロジェクト id）に保存する
（`src/editor/audioStore.ts`）。サーバーの `Project.audio` にはファイル名・サイズ・種類だけを
持つ。

したがって、サーバーの「音声あり」の記録とブラウザの本体はずれることがある（ブラウザの
データ消去・別の端末やブラウザで開いた・保存の失敗など）。

### 7.2 音声バー（画面下端）

音声が無いときは「音声ファイルを取り込むと、発言の時刻から再生できます。」と
「音声ファイルを選ぶ」ボタン（`audio/*` と `video/*` を受け付ける）を出し、「音声はこの
ブラウザ内にのみ保存され、サーバーへは送信されません」と添える。

音声があるときは、再生／一時停止、3秒戻す／進める、再生位置と長さ、シークバー、
速度（0.5〜2倍の6段階から選ぶ）、「再生に合わせて追従」、ファイル名、「音声を外す」を並べる。

### 7.3 選んだとき

- 選んだファイルは**保存の完了を待たずに再生できる**（大きなファイルは保存に時間がかかる）
- 保存中は「このブラウザに保存中…（終わるまで画面を移らないでください）」を出し、
  `beforeunload` で引き止める
- 保存は IndexedDB のトランザクションが完了した時点で成功とし（`durability: "strict"`）、
  さらに読み直してサイズが一致することを確かめる。要求の成功だけで「保存できた」と
  していたため、容量不足などで中断されても気づけなかった
- 保存に失敗したら、理由を添えて「このブラウザに保存できませんでした（…）。このページを
  開いている間は再生できますが、画面を移ると選び直しが必要です。」を出す

### 7.4 開いたとき

- `Project.audio` があり、このブラウザに本体があれば読み込んで再生できる状態にする
  （読み込み中は「音声を読み込み中…」）
- 本体が無ければ、音の出ない再生バーではなく**選び直す画面**を出す：
  「「ファイル名」はこのブラウザには保存されていません。もう一度選んでください
  （ブラウザのデータを消した・別の端末やブラウザで開いた・保存に失敗した、などの場合）。」と
  「音声ファイルを選ぶ」ボタン。「音声を外す」を先に押す必要はない

### 7.5 外す・削除する

- 「音声を外す」で IndexedDB の本体を消し、`Project.audio` を `null` にする（自動保存）
- プロジェクトを削除すると、このブラウザの音声も消す
- プロジェクト一覧の「音声あり」は、**このブラウザに本体が保存されているものだけ**に付ける
  （サーバーの記録だけでは付けない）

### 7.6 再生との連動

- 表の時刻をクリックするとその位置から再生する。表の行をクリックしたときも、その行が時刻を
  持っていればそこへ頭出しする
- 再生中は対応するブロックを1行だけハイライトし、「再生に合わせて追従」がオンなら
  そのブロックが見える位置へ左右のペインを動かす

`tests/audio.test.mjs` が再生・シーク・追従・ショートカットと音声がサーバーへ送られないことを、
`tests/audiostore.test.mjs` が画面を移っても外れないこと・本体が無いときの選び直し・
保存失敗時の表示を検証している。

## 8. 左右のスクロール連動

既定でオン（2段目の「⇅ 連動中」で切り替え、設定は保存される）。「両方」表示のときだけ効く。

左右のペインは行の折り返し方が違うため、高さが倍近く変わる。画素やスクロール率では
対応づけできないので、**ブロック（＝表の1行）を共通の目印**にして、「上端に見えて
いるのは何番のブロックの何割の位置か」を移し替える。ブロックの中も割合で補間するので、
長い発言の途中でスクロールしてももう片方が止まったままにならない。

表の行をクリックしたとき、未割り当てへジャンプしたとき、音声の再生に追従するときは、
両方のペインがその発言へ揃う。

`tests/scrollsync.test.mjs` が、左右で高さが1.8倍違う状態でも上端に同じ発言が来ることを
検証している。

## 9. ショートカット

| キー | 動作 |
|---|---|
| `Space` | 再生 / 一時停止（入力欄の外） |
| `Shift` + `Space` | 編集中でも再生 / 一時停止 |
| `Alt` + `←` / `→` | 3秒 戻す / 進める |
| `Alt` + `↑` / `↓` | 再生速度（0.5〜2.0、0.25刻み） |
| `Alt` + `J` | 未割り当ての次の箇所へ |
| `Alt` + `D` | カーソル位置に区切り（時:分:秒の時刻が付く。第6.2章） |
| `Alt` + `A` | 話者を選ぶ（`@` を入力してピッカーを開く） |
| `Alt` + `1` / `2` / `3` | 左のみ / 両方 / 右のみ |
| `Alt` + `-` / `=` | 文字サイズ（11〜32px）。`=` の代わりに `;` も効く |
| `Alt` + `S` | スクロール連動の切替 |
| `Ctrl` + `Z` / `Ctrl` + `Shift` + `Z` | 取り消し / やり直し（ブラウザ標準） |

- **Mac では `Alt` の代わりに `Option`（⌥）キーを使う。** キーの判定は `KeyboardEvent.code`
  で行うので、Option を押したときに入力される記号に左右されない
- 「入力欄の外」は、テキストエリア・入力欄・セレクト・`contenteditable` 以外を指す
- `Ctrl+Space` を使わないのは、Windows / macOS で入力ソース切り替え等の OS 標準
  ショートカットに割り当てられていることが多く、ブラウザまでイベントが届かないため
- メモ（第11章）の入力中は、`Space` は空白の入力になる。`Alt` + `D` / `A` / `J` は
  生テキスト側を書き換えたりフォーカスを移したりするため、メモの中では効かせない。
  再生まわり（`Shift` + `Space`、`Alt` + 矢印）と表示の切り替えは効く

「使い方」モーダル（`HelpModal.tsx`）には7項目（再生／一時停止、3秒戻す・進める、再生速度、
未割り当ての次へ、区切り、話者、取り消し・やり直し）だけを載せ、画面上に専用のボタン・表示が
既にあるもの（ペイン切替・文字サイズ・スクロール連動）は載せていない。モーダルには
入力ルール（`@` / `--` / `--@時刻` の3つの表記 / `Alt` + `D` の時刻 / `#`）と、Mac の
`Option` キーの注記もある。`Escape` か背景クリックで閉じる。

## 10. 表をコピーする機能について

`TableView.tsx` の「表をコピー」ボタンは**削除した。** 出力は③に一本化する。

同じ機能が2か所にあると、列を選べるのはどちらかが分からなくなる。この画面の表形式
ビューは、話者割り当ての確認用という位置づけ。ペインヘッダにも「話者割り当ての確認用です。
コピーは③出力画面から行ってください。」と明示している。

表の話者列は、割り当て済みなら「✓ 所属/氏名」、未割り当てなら「未割り当て」と出す。

## 11. メモ

担当者が参加者の正式名称・フルネームや、誤変換されやすい語を見ながら作業できるよう、
プロジェクト単位の自由記述メモを置く（`Project.memo`。全体仕様 第4.2章）。
部品は②と共通の `src/components/MemoPanel.tsx`。**人が読むためのもので、AI には渡さない。**

### 位置と表示

- **画面の右下**に `position: fixed` で浮かせる。画面下端の音声バーにかからないよう、
  その上に出す（②は左下）
- 閉じているときは小さなタブ「メモ」だけを出す。**既定は閉じた状態**
- 開くとプレーンテキストの `textarea` 1つ。開いた時点でフォーカスが移る。見出しに
  「担当者用。整文の AI には渡しません」と添え、「閉じる」ボタンを置く
- 高さは内容に合わせて伸び、**画面の 1/3 程度（`max-height: 33vh`）**で止まる。超えた分は
  `textarea` の中でスクロールする
- 開いても下のレイアウトはずらさず、**上に重ねて表示する**。「両方」表示では右ペインの表に、
  **「左のみ」表示では左ペインの編集欄の右下に重なる。**重なった部分を編集したいときは
  メモを閉じる
- 話者ピッカー（`.suggest`）とモーダルはメモより手前に出る（`z-index` はメモ 30、
  ピッカー 50、モーダル 200）

### 入力と保存

- 入力内容は解析・整形しない。打ったものがそのまま保存される（前後の空白・空行も残す）
- 保存はこの画面の既存の保存処理に乗せる（900ms デバウンス、`beforeunload` / `pagehide`。第2章）
- **`memo` は変更したときだけ PATCH に含める。** ①と②を別タブで開いていても、メモを
  触っていない側が古い内容で上書きしないようにするため（全体仕様 第4.6章）
- 開閉状態は `UserSettings.memoOpen` に保存する。①②で共通の値で、開閉のたびに
  `{ memoOpen }` だけを `PATCH /api/settings` へ送る
- 担当者も編集できる。権限の区別は設けない

### 固有名詞リストとの違い

②の固有名詞リスト（`Project.glossary`）は「AI に表記を変えさせない語」として整文に渡す。
メモは整文には一切渡さず、人が参照するだけのもの。誤変換の直し方を書いておいても、
直すのはこの画面で人が行う（第12章）。

`tests/memo.test.mjs` が、保存・再読み込み・①②間での共有・開閉状態の保存・別タブでの
上書き防止・入力中の `Space` で再生しないことを検証している。

## 12. 運用上の注意

### 長い発言は分割したほうがよい

実データで4,000字規模の1発言を整文にかけたところ、以下が起きた。

- 出力トークンの上限に達して途中で切れる（②で `max_tokens` を 8192 に引き上げ済みだが、
  根本的には長すぎる）
- 段落の再構成が入り、整文の範囲を超えた書き換えに近づく

話題の切れ目で `--` を入れて分割すると、②の精度が上がる。

### 誤変換はこの画面で直す

②の整文は誤変換を推測で直さない。「教会」→「協会」のような明らかな誤りも、この画面で
直さない限りそのまま出力される。

これは意図的な仕様である。AI に推測で直させると、**出力が自然な日本語になるため、
間違っていても人が気づけない**（全体仕様 第1章）。
