URL: `/projects/{id}`
担当工程: ステップ1（発言の区切りと話者の割り当て）、ステップ2（誤字脱字・固有名詞の誤変換の修正）

## 1. 画面の役割

左ペインで生テキストを編集し、右ペインに表を表示する2ペイン構成。

| 記法 | 意味 |
|---|---|
| `@所属/氏名` | 話者の指定 |
| `--` | 発言の区切り |
| `--@12.3` | 時刻付きの区切り（数字は秒） |
| `#` | 議題見出し |

音声を聞きながら編集できるよう、タイムスタンプと連動再生する機能がある。音声はサーバーに
送らず、ブラウザの IndexedDB（`src/editor/audioStore.ts`）に保存する。テキスト
（`rawText`・参加者）はサーバー側の KV に保存される（全体仕様 第4.1章）。

### この画面で確定させること

後続の工程は、この画面の出力を確定済みとして扱う。

- 発言の区切り位置
- 話者の割り当て
- **固有名詞・誤変換の修正** … ②の整文では推測による修正を一切行わないため、
  ここで直さなければ誤ったまま出力される

## 2. ツールバー

情報を「どこにいるか」と「今の作業状態」で2段に分ける。

| 段 | class | 内容 |
|---|---|---|
| 1段目 | `.topbar-main` | 画面間ナビ（`ProjectNav`：「← 一覧」／話者整理・整文・出力）／ 議事録名の入力欄 ／「取り込み・参加者」／「使い方」 |
| 2段目 | `.topbar-sub` | 保存状態 ／ ブロック数と未割り当て件数 ／「次の未割り当てへ」／ ペイン切替（左・両方・右）／「⇅ 連動中」／ 文字サイズ |

- 1段目と2段目は背景の濃淡で区別する。2段目に `--panel-sub` を敷き、下に境界線を引く。
  **色相は変えない。**「保存済み」バッジや未割り当て件数の色が埋もれるため
- ログインユーザーのメールアドレスは表示しない。ログアウトはプロジェクト一覧側にあり、
  この表示に機能が紐づいていない
- 議事録名は1段目の入力欄で直接編集する（自動保存の対象）

### 保存

`title` / `rawText` / `participants` / `mru` / `audio` を **900ms デバウンス**で
`PATCH /api/projects/{id}` へ送る（②は2秒。こちらは打鍵のたびに走るため短くしてある）。
`beforeunload` で引き止め、`pagehide` で `keepalive` 付きの送信を行う。

表示設定（`UserSettings`）は 400ms デバウンスで `PATCH /api/settings` へ別に送る。
③専用の設定（`exportIncludeTime` など）はこの画面では変更しないため、受け取った値を
そのまま送り返している。

## 3. 「取り込み・参加者」ドロワー

1段目の「取り込み・参加者」で開閉する。**未取り込みのプロジェクトでは既定で開く**
（`useState(!project.imported)`）。

上段を2列にする。左列に手順リスト（4項目。取り込み・参加者・音声の済み状態に応じて
✓が付く）、右列に JSON 取り込みエリア。その下に参加者の登録。

「自動話者分離の切れ目に `--` をあらかじめ入れる」のチェックボックスは、見出しの横では
なくドロップエリアの直上に1行で置く。見出しの横だと折り返して崩れる。

固有名詞の登録はここに置かない（②の整文画面にある）。使う画面に設定を置く。

## 4. 参加者の登録

**テキストエリア1つに統一する。** 個別の入力欄グリッド、各行の × ボタン、
「＋1人追加」「まとめて貼り付け」等のボタンはすべて廃止した。

- 1行1人。テキストエリアの内容がそのまま参加者リストになる。行を消せばその参加者も消える
- 高さは `rows={10}` で固定し、超えたら内部でスクロールさせる。参加者が30名でも
  パネルの高さが変わらないようにするため
- 解析は `parseBulk()`（`/`／全角スラッシュ／タブ／半角・全角スペースで所属と氏名に分割）。
  区切りが無い行は氏名だけの参加者になる
- **確定はフォーカスが外れた時点**（`onBlur`）。入力のたびに解析すると、途中の文字列で
  参加者が登録される
- 打った内容は整形し直さない（「●●小 太田」を「●●小/太田」に書き換えない）
- 下に「○名 登録済み」（確定済みの件数）と、「所属・氏名を変更すると、既にその人に
  割り当てた `@` は外れます」を表示する

### `id` の扱い

確定時に、`participantLabel`（`所属/氏名`）が変わっていない人の `id` を `keepIds()` が
引き継ぐ。同一ラベルが複数ある場合は上から順に割り当てる。

`id` を毎回振り直してもメンションは壊れないが、**MRU（直近に使った話者）が `id` で
紐づいているため、テキストエリアを触るたびにリセットされる。**

### メンションとの関係（既知の制約）

`@` メンションは `rawText` に `@所属/氏名` という文字列として保存されており、
`parseDoc()` がラベル一致で照合している。`id` は `rawText` に現れない。

したがって所属・氏名を変更すると、`rawText` 内の古いラベルは一致しなくなり、その人に
割り当てたメンションは未割り当てに戻る。自動置換は行わず、注意書きの表示にとどめる。

### `@` の解釈

- 候補に出るのは**事前登録した参加者だけ**。長いラベルから順に照合するので、
  「●●小/太田」と「太田」を取り違えない
- 登録されていない `@` は話者として拾わない。日本語は語の切れ目に空白が無いため、
  当てずっぽうに拾うと一文まるごと氏名になってしまう。印だけ付けて本文として残し、
  打ち間違いに気づけるようにする
- 1ブロックに `@` を2つ書けば「A / B」と並べて表示できる（発言の重なり用）

## 5. JSON の取り込み

WhisperX の出力 JSON（`assign_word_speakers()` の戻り値をそのまま `json.dump()` したもの）を
受け付ける。実装は `src/editor/whisperx.ts`。

### 期待する構造

```json
{
  "segments": [
    {
      "text": "おはようございます",
      "start": 12.3,
      "end": 13.1,
      "speaker": "SPEAKER_00",
      "words": [
        {"word": "おはよう", "start": 12.3, "end": 12.8, "speaker": "SPEAKER_00"},
        {"word": "ございます", "start": 12.8, "end": 13.1, "speaker": "SPEAKER_00"}
      ]
    }
  ],
  "language": "ja"
}
```

### 読み取り仕様

- 最優先で `segments[].words[]` を読む。無ければ `word_segments`、それも無ければ
  セグメント単位にフォールバック
- 単語のキーは `word` でも `text` でも可
- 話者は単語単位の `speaker` を優先し、無ければセグメントの `speaker` を使う
- 話者が特定できない場合もエラーにはならず「話者未確定」として扱われる
- `language` キーは読み込み時に使用していない
- **単語単位のタイムスタンプが重要。** 人手でどこを分割しても、その位置の単語が持つ
  実際の時刻を使うため。文字数比での按分は行わない

取り込み結果（`words` / `norm` / `normWordIdx`）は `p_{id}_words` に保存する。

### 自動話者分離の位置づけ

**確定情報として使わない。**

- 発言が重なることが多く、自動判定の精度には期待していない
- 話者が切り替わったと判定された位置に、編集画面で**オレンジの点線**を表示するだけ
- 実際の話者名は、人が事前登録した参加者リストから選んで確定させる

pyannote に求めているのは「話者が変わった可能性がある」という参考情報であり、
正確な話者特定ではない。取り込み時のチェックを外さなければ、点線の位置にあらかじめ
`--@秒` を入れた状態で始められる。精度が低いと感じたらチェックを外して取り込む。

## 6. 時刻の求め方

**時刻はブロック自身が持つ。** 区切り記号に `--@12.3` の形で書き込まれており、表示や
連動のたびに引き直すことはしない（`Block.time`）。

- 取り込み時、各セグメントの先頭単語の実測値を区切りへ書き込む
- `Alt+D` で区切りを入れたときは、その瞬間に一度だけ単語データを引いてカーソル位置の
  時刻を求め、区切りへ焼き付ける。単語データで引けないときは、いま聞いている再生位置で代用する
- 再生位置に対応するブロックは「時刻が再生位置以下である最後のブロック」
  （`blockAtTime()`）。時刻を持たないブロックは連動の対象外として飛ばす（時刻列は空欄）
- 本文を編集しても時刻はずれない。区切りごと消したときだけ無くなる

文字数比などによる按分はしていない。また、再生位置から単語データと文字オフセットを
経由してテキスト位置を逆引きすることもしていない。逆引きは本文を編集した時点で対応が
崩れ、ブロックを削除するとハイライトが無関係な位置へ飛ぶため。

単語データ（`ProjectWords`）は、ブロックを分割する瞬間の時刻取得と、pyannote の
話者交代ヒントの位置合わせにだけ使う。

## 7. 左右のスクロール連動

既定でオン（2段目の「⇅ 連動中」で切り替え、設定は保存される）。

左右のペインは行の折り返し方が違うため、高さが倍近く変わる。画素やスクロール率では
対応づけできないので、**ブロック（＝表の1行）を共通の目印**にして、「上端に見えて
いるのは何番のブロックの何割の位置か」を移し替える。ブロックの中も割合で補間するので、
長い発言の途中でスクロールしてももう片方が止まったままにならない。

表の行をクリックしたとき、未割り当てへジャンプしたとき、音声の再生に追従するときは、
両方のペインがその発言へ揃う。

`tests/scrollsync.test.mjs` が、左右で高さが1.8倍違う状態でも上端に同じ発言が来ることを
検証している。

## 8. ショートカット

| キー | 動作 |
|---|---|
| `Space` | 再生 / 一時停止（入力欄の外） |
| `Shift` + `Space` | 編集中でも再生 / 一時停止 |
| `Alt` + `←` / `→` | 3秒 戻す / 進める |
| `Alt` + `↑` / `↓` | 再生速度（0.5〜2.0、0.25刻み） |
| `Alt` + `J` | 未割り当ての次の箇所へ |
| `Alt` + `D` | カーソル位置に区切り（その位置の時刻が付く） |
| `Alt` + `A` | 話者を選ぶ（`@` を入力） |
| `Alt` + `1` / `2` / `3` | 左のみ / 両方 / 右のみ |
| `Alt` + `-` / `=` | 文字サイズ（11〜32px） |
| `Alt` + `S` | スクロール連動の切替 |
| `Ctrl` + `Z` / `Ctrl` + `Shift` + `Z` | 取り消し / やり直し（ブラウザ標準） |

`Ctrl+Space` を使わないのは、Windows / macOS で入力ソース切り替え等の OS 標準
ショートカットに割り当てられていることが多く、ブラウザまでイベントが届かないため。

「使い方」モーダル（`HelpModal.tsx`）には7項目だけを載せ、画面上に専用のボタン・表示が
既にあるもの（ペイン切替・文字サイズ・スクロール連動）は載せていない。

## 9. 表をコピーする機能について

`TableView.tsx` の「表をコピー」ボタンは**削除した。** 出力は③に一本化する。

同じ機能が2か所にあると、列を選べるのはどちらかが分からなくなる。この画面の表形式
ビューは、話者割り当ての確認用という位置づけ。ペインヘッダにもその旨を明示している。

## 10. 運用上の注意

### 長い発言は分割したほうがよい

実データで4,000字規模の1発言を整文にかけたところ、以下が起きた。

- 出力トークンの上限に達して途中で切れる（②で `max_tokens` を 8192 に引き上げ済みだが、
  根本的には長すぎる）
- 段落の再構成が入り、整文の範囲を超えた書き換えに近づく

話題の切れ目で `--` を入れて分割すると、②の精度が上がる。

### 誤変換はこの画面で直す

②の整文は誤変換を推測で直さない。「教会」→「協会」のような明らかな誤りも、この画面で
直さない限りそのまま出力される。

これは意図的な仕様である。AI に推測で直させると、**出力が自然な日本語になるため、
間違っていても人が気づけない**（全体仕様 第1章）。
